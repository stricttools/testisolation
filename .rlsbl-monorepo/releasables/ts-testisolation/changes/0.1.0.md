## 0.1.0

First release of the stricttest npm package.

<details>
<summary>Context</summary>

The Node member of the same floor, in the shape node:test allows: isolate(t)
binds to a TestContext directly and undoes itself when the test finishes, and
the package detects overlapping isolations rather than letting one test's HOME
leak into another's. Bare-run refusal is a function the consumer calls, because
node --test runs each test file in its own child process and an --import setup
module can never learn how large the run is. Like the Go module it ships no
socket guard, and no push guard either -- patching node:child_process is equally
porous, and transport lockdown already closes the outcome.

</details>

### Features

- [ts-stricttest] **New: the `stricttest` npm package.** One `isolate(t)` call gives a Node test a throwaway `HOME` and XDG directory set, an empty git config with a throwaway identity, `GIT_ALLOW_PROTOCOL=file` with git's ssh and proxy helpers pinned to `/bin/false`, and an environment stripped of every ambient credential -- all restored when the test ends. `node:test`'s `TestContext` binds directly with no adapter. Granular helpers (`throwawayHome`, `isolateGitConfig`, `lockdownTransports`, `stripCredentials`, `chdir`) and a closed `preserve` enum for toolchain caches ship alongside it, and `requireSandbox` refuses a run happening outside the sandbox runner. The credential list and the preserve enum are held identical to the pytest plugin's and the Go module's by a cross-language test.
